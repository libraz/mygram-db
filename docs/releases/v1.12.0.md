# MygramDB v1.12.0 Release Notes

**Release Date:** 2026-11-04
**Type:** Feature — Tagged GTIDs, MySQL 26.x & Shared Binlog Decoding
**Previous Version:** v1.11.1

---

## Overview

MygramDB now decodes the binlog through libmybinlog, a separate library that carries the wire-format rules for both MySQL and MariaDB. The in-tree decoder is gone. This is what lets a source using MySQL tagged GTIDs replicate, which v1.11.x refused at startup.

MySQL 26.x Innovation releases join the supported series. One server setting that was never checked, `log_bin=ON`, is now verified at startup.

**Highlights:**

- **Tagged GTIDs replicate.** A source whose `gtid_executed` holds `uuid:tag:n` entries starts, streams and resumes across reconnects.
- **MySQL 26.x is supported** alongside the 8.4 and 9.7 LTS series.
- **One binlog decoder for MySQL and MariaDB.** Framing, checksums, `TABLE_MAP`, GTID, `QUERY` and rows events are decoded by libmybinlog, and malformed input is refused instead of guessed at.

---

## Upgrade actions required

### The source must run `log_bin=ON`

A server with binary logging off has no binlog to stream, but startup did not check it. It is now refused at startup with `2008`, like the other unmet settings in `spec/config-keys.md`. Every working setup already has binary logging on, so this affects only a misconfigured source.

### `gtid=,` is rejected

A `replication.start_from` of `gtid=` followed by nothing but separators is now a configuration error. Give a real position, or use `snapshot` or `latest`.

---

## Behavior changes

### Replication

- A MySQL 8.4+ source with tagged GTIDs in `gtid_executed` is no longer refused with `2005`. Tagged GTID events are decoded and recorded in the replication position.
- A bare `UUID:tag:N` start position means "through N" and is widened to `UUID:tag:1-N`, as `UUID:N` is widened to `UUID:1-N`.
- Row values decoded from the binlog render with the same text the snapshot path produces.
- Malformed row data that used to be decoded by guesswork now fails with `2014`: a zero-width BLOB length prefix, a zero ENUM/SET pack length, the packed integers `0xFB`/`0xFF`, and a column count of 0.
- A GTID event with GNO 0 or `INT64_MAX` is an undecodable event (`2017`) and the reader reconnects from the applied position.
- A malformed MariaDB `COMPRESSED` column is reported as an invalid value rather than as an undecodable event.

Compressed transaction events and `PARTIAL_UPDATE_ROWS` stay refused, as before.

---

## Compatibility

- MySQL 8.4, 9.7 and 26.x; MariaDB 10.11, 11.x and 12.x. The binlog format, GTID encoding and required settings of 26.x are the same as 9.7.
- Dumps written by v1.11.x load without conversion. The TCP and HTTP surfaces are unchanged.

---

## Build

- libmybinlog v0.3.1 is fetched by `third_party/CMakeLists.txt`. `MYBINLOG_SOURCE_DIR` points the build at a local checkout for offline builds (see `CONTRIBUTING.md`).
- The minimum CMake version rises to 3.18, the floor libmybinlog declares.
- macOS builds work against the macOS 27 SDK. The SDK ships partial `unicode/` headers that shadowed ICU's, because the build put the SDK's `usr/include` ahead of every dependency.
- CRoaring v5.4.0 and cpp-httplib v0.64.0. The new cpp-httplib answers 501 to a transfer coding other than a single `chunked` and bounds how much of an unread request body it skips.
