# MygramDB v1.8.1 Release Notes

**Release Date:** 2026-07-16
**Type:** Correctness & Reliability Hardening
**Previous Version:** v1.8.0

---

## Overview

Version 1.8.1 is a correctness- and reliability-focused release that hardens the replication, snapshot, and long-running-operation paths against data loss and inconsistent state, tightens process-wide resource admission, and closes an access-control gap on HTTP health endpoints. It also lands additive, ABI-safe C client and configuration surface (new raw boolean/highlight functions, a versioned client config struct, a `boolean` filter type, and V2 dump restore limits) without breaking existing callers.

No breaking changes. All new configuration keys and the new C client config struct are backward compatible; existing configurations and the legacy C ABI continue to work unchanged.

**Highlights:**

- **Critical snapshot/binlog position gap** — snapshots now capture a conservative GTID lower bound before opening the consistent snapshot, so commits can no longer be permanently skipped
- **Critical SYNC data integrity** — SYNC builds replacement state on the side, swaps only on success, rolls back a failed restart, and resumes the shared reader from its pre-SYNC drained GTID so other tables do not lose events
- **Critical MariaDB compressed-event handling** — `log_bin_compress=ON` and compressed event IDs 165–168 now fail closed before advancing the GTID
- **DDL schema-compatibility enforcement** — a drop, rename, or semantic change to a monitored column stops replication before advancing the GTID instead of silently diverging
- **Fail-closed HTTP access control** — an empty, omitted, or invalid CIDR allow list now denies access instead of allowing all; `/health/detail` is access-controlled like other endpoints
- **Long-running operation coordinator** — SYNC, DUMP SAVE/LOAD, OPTIMIZE, and auto snapshot pass through a single atomic admission point and can no longer overlap
- **Process-wide reactor memory admission** — aggregate pending request/response memory is capped across all connections, not just per-connection
- **ABI-safe C client and config additions** — raw boolean search/highlight, `MygramClientConfigV2_C` (UDS, async DUMP SAVE timeout), a `boolean` filter type, and V2 dump restore limits
- **14 commits** since v1.8.0

## Critical Fixes

### 1. Snapshot/binlog position gap could permanently skip commits

**Type:** Bug Fix
**Severity:** Critical

Initial and shared snapshots opened the consistent snapshot before establishing a GTID lower bound, so transactions committed in the window around snapshot start could be neither captured by the snapshot nor replayed from the binlog. Snapshots now capture a conservative GTID lower bound before opening the consistent snapshot, closing the gap.

**Files Changed:**

- `src/loader/initial_loader.cpp`, `src/loader/initial_loader.h`
- `src/app/server_orchestrator.cpp`

### 2. SYNC could lose events for unrelated tables

**Type:** Bug Fix
**Severity:** Critical

A failed SYNC restart could leave replacement state partially applied and advance the shared reader past events other tables had not yet consumed. SYNC now builds replacement state on the side and swaps only after success, rolls back a failed reader restart, and resumes the shared reader from its pre-SYNC drained GTID so co-monitored tables do not miss events.

**Files Changed:**

- `src/server/handlers/dump_handler.cpp`, `src/server/handlers/command_handler.cpp`
- `src/server/http_server.cpp`

### 3. MariaDB compressed binlog events could advance the GTID on unhandled data

**Type:** Bug Fix
**Severity:** Critical

With `log_bin_compress=ON`, compressed event IDs 165–168 were not decoded, risking a silent GTID advance past events that were never applied. These paths now fail closed before GTID advancement.

**Files Changed:**

- `src/mysql/binlog_event_parser.cpp`, `src/mysql/binlog_event_types.h`
- `src/mysql/binlog_reader.cpp`

### 4. Snapshot and binlog paths could materialize text/filters differently

**Type:** Bug Fix
**Severity:** High

The initial snapshot and row-based binlog paths derived text and filter values through separate code, allowing subtle disagreements (absent vs. NULL vs. present state, boolean filters, and TIMESTAMP timezone handling). A shared text-source materializer and filter-value converter now drive both paths so they produce identical results; every MySQL session is pinned to UTC so TIMESTAMP rendering matches binlog decoding, and a configured text column absent from a FULL row image fails closed instead of indexing empty text.

**Files Changed:**

- `src/mysql/text_materializer.h`, `src/mysql/rows_parser_filter.cpp`
- `src/mysql/binlog_event_parser.cpp`, `src/mysql/binlog_event_processor.cpp`, `src/mysql/binlog_filter_evaluator.cpp`
- `src/mysql/connection.cpp`, `src/loader/initial_loader.cpp`

## Replication & Lifecycle Hardening

### 5. DDL schema-compatibility enforcement

The binlog reader now fingerprints the configured primary-key, text, and filter columns at startup and revalidates after each DDL on a monitored table. Unrelated `ADD COLUMN`/`ADD INDEX` operations stay compatible; a drop, rename, or semantic change to a monitored column marks the reader schema-incompatible, stops before advancing the GTID, and requires an explicit `SYNC` or configuration change to recover.

**Files Changed:** `src/mysql/ddl_schema_validator.cpp`, `src/mysql/ddl_schema_validator.h`, `src/mysql/binlog_reader*.cpp`

### 6. GTID handoff, reconnect, and failover fail closed

MySQL and MariaDB GTID validation, snapshot handoff, reconnect, and failover rollback are hardened. Unsafe statement `QUERY` and XA paths are rejected before they can publish data or advance the applied position. Candidate MySQL connections are validated before publication, and a failed reader restart restores the previous connection and replication position. Per-table replay fences and catch-up waiting were added, along with MariaDB stream-capability setup and GTID wait utilities.

**Files Changed:** `src/app/mysql_reconnection_handler.cpp`, `src/app/server_orchestrator.cpp`, `src/app/application.cpp`, `src/mysql/binlog_event_parser.cpp`

### 7. Long-running operation coordinator

`SYNC`, `DUMP SAVE`, `DUMP LOAD`, `OPTIMIZE`, and automatic snapshots — all of which pause replication, replace live stores, or rebuild index state — now pass through `OperationCoordinator`, a single atomic admission point. Each entry point acquires a token and returns a descriptive error naming the in-progress operation on conflict; shutdown blocks new work while draining the active token. `DUMP LOAD` also forwards the configured restore limits to the V2 reader.

**Files Changed:** `src/server/operation_coordinator.cpp`, `src/server/operation_coordinator.h`, `src/server/handlers/dump_handler.cpp`, `src/server/sync_operation_manager.cpp`, `src/server/snapshot_scheduler.cpp`

## Server & Reactor Correctness

### 8. Fail-closed HTTP access control

The CIDR allow list is now applied to every non-probe HTTP request, so an empty, omitted, or invalid list denies access instead of allowing all. The bypass is restricted to `/health/live` and `/health/ready`; `/health/detail`, which exposes operational data, now follows the same access control as other endpoints.

**Files Changed:** `src/server/http_server.cpp`

### 9. Reactor ownership, lifecycle bounds, and reused-FD dispatch

Connection publication is ordered against shutdown by taking the mux lifecycle lock before clearing connections, so a `Register` cannot publish a connection after the map is cleared; `Start()` rejects stale connections left from a prior lifecycle. Connection registrations are tokenized to prevent a reused file descriptor from dispatching to a stale handler. Read/frame budgets and watermarks prevent single-client starvation, HTTP lifecycle transitions are serialized, reactor shutdown closes every registered connection exactly once, and shutdown drain failures propagate as errors.

**Files Changed:** `src/server/io_reactor.cpp`, `src/server/io_reactor.h`, `src/server/reactor_connection.cpp`, `src/server/reactor/*_multiplexer.cpp`

### 10. Process-wide reactor memory admission

`api.tcp.max_total_buffered_bytes` caps the aggregate of pending request frames and unsent responses across all clients, preventing per-connection limits from multiplying into unbounded process memory.

**Files Changed:** `src/server/reactor_connection.cpp`, `src/server/http_server.cpp`

## Cache & Query Correctness

### 11. Tagged binary cache keys eliminate cross-field collisions

The character-concatenated query cache key is replaced with a versioned, length-prefixed encoding in which every field carries a type tag. Field boundaries are now injective, so search text cannot collide with filter structure; the exact canonical table key is preserved, and filters sort by the full column/operator/value tuple.

**Files Changed:** `src/query/query_normalizer.cpp`, `src/query/query_normalizer.h`

### 12. Cache semantic and ABA correctness

Cache keys include execution semantics and synonym revision, and text-sensitive entries invalidate safely. Monotonic epochs and entry generations prevent stale deferred work from deleting or reinserting a newer incarnation of an entry. `cache.max_memory_mb` is enforced as a shared budget across cache entries, container/LRU/table indexes, and invalidation metadata, and INFO/Prometheus expose the shared accounted cache total including that overhead.

**Files Changed:** `src/cache/cache_manager.cpp`, `src/cache/query_cache.cpp`, `src/cache/invalidation_manager.cpp`, `src/cache/invalidation_queue.cpp`

### 13. Literal reserved-word search, required empty strings, and synonym activation

Quoted parser provenance is preserved across the TCP/client paths, so quoted reserved terms stay literal. Required string filters now distinguish an explicitly empty value from an omitted field. Enabled synonym dictionaries fail startup when absent or invalid, while a failed reload preserves the last published dictionary.

**Files Changed:** `src/query/query_parser*.cpp`, `src/query/synonym_dictionary.cpp`, `src/client/mygramclient.cpp`

## Storage & Configuration

### 14. V2 dump restore limits and replacement safety

`dump.restore_memory_budget_mb` and `dump.restore_max_section_mb` bound the memory staged during a V2 restore so a corrupt or malicious dump cannot exhaust memory before the atomic swap. `ReplaceLoadedTables` rejects duplicate or null table replacements and propagates the failure instead of applying a partial swap. V1/V2 dump compatibility metadata is extended so `verify_text` semantics survive save and load.

**Files Changed:** `src/storage/dump_format_v2.cpp`, `src/storage/dump_format_v2.h`, `src/storage/document_store_persistence.cpp`

### 15. Filter schema validation and boolean filter type

Declaring a column as both a required and optional filter with conflicting types is now rejected at load, with the merged view exposed via `BuildUnifiedFilterConfigs`. A `boolean` filter type restricted to equality and NULL operators was added. `dump.restore_memory_budget_mb`/`dump.restore_max_section_mb` are exposed as configuration, and invalid IPv4 CIDRs in `network.allow_cidrs` are rejected at load time.

**Files Changed:** `src/config/config.cpp`, `src/config/config.h`, `src/config/config-schema.json`

## Migration Guide

No migration steps required. All new configuration keys (`dump.restore_memory_budget_mb`, `dump.restore_max_section_mb`, the `boolean` filter type) are optional and backward compatible, and the legacy C client ABI is unchanged.

Two behavioral hardening notes worth reviewing before upgrading:

- **HTTP access control is now fail-closed.** If `network.allow_cidrs` is empty, omitted, or invalid, all non-probe HTTP requests (including `/health/detail`) are denied. Configure a valid allow list if you rely on HTTP access.
- **DDL on monitored columns can now stop replication.** A drop, rename, or semantic change to a configured primary-key/text/filter column marks the reader schema-incompatible and stops before advancing the GTID; recover with an explicit `SYNC` or a configuration change. Unrelated `ADD COLUMN`/`ADD INDEX` operations are unaffected.
