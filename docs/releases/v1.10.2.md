# MygramDB v1.10.2 Release Notes

**Release Date:** 2026-09-28
**Type:** Replication Decoding, Client/Server Quoting & Surface Agreement
**Previous Version:** v1.10.1

---

## Overview

Every change in this release is corrective. No capability was added that the project had not already promised, and no configuration key or default changed for any other reason.

Most of the fixes fall into three groups. Replication read some column metadata in the wrong byte order or did not consume it at all, so a row could be decoded from the wrong offset without any error. The client libraries and the CLI quoted search text by rules that differed from the server's, so full-width spaces, quoted keywords and web-syntax expressions could reach the server meaning something other than what was sent. And a number of requests still behaved differently on TCP and HTTP. In each case one rule now serves every caller.

Several corrections change whether a configuration starts or whether replication keeps running. Those are listed first.

**Highlights:**

- **Row images decode at the right offsets** — TABLE_MAP metadata is read per column type in the server's byte order, so `DECIMAL`, `CHAR`, `ENUM`, `SET`, `JSON` and `GEOMETRY` columns no longer shift or misread the columns after them
- **MariaDB `COMPRESSED` columns replicate** — `VARCHAR ... COMPRESSED` and `TEXT ... COMPRESSED` columns are inflated from the row image and index the same text the initial load reads
- **Clients send what the caller wrote** — the C++ SDK, the C ABI and `mygram-cli` quote search text by the server's own rule, including Unicode whitespace and literal keywords
- **Dumps that save also restore** — `DUMP SAVE` refuses a document the restore path would reject, instead of writing a dump that later fails to load
- **Tested against every supported LTS** — the e2e matrix covers MySQL 8.4 and 9.7 and MariaDB 10.11, 11.8 and 12.3

## Upgrade actions required

Read this section before upgrading. The rest of the notes are informational.

### Configurations that no longer start

| Configuration | What was happening | What happens now |
|---|---|---|
| `dump.load_on_startup: true` with `replication.start_from` set to `latest` or `gtid=...` | Replication started from the configured position instead of the restored dump's GTID, skipping every change made between the dump and the restart | Refused at startup, as `auto_initial_snapshot` already was. Use `start_from: snapshot` |
| `cache.ttl_seconds`, `cache.eviction_batch_size`, `cache.invalidation.batch_size` or `cache.invalidation.max_delay_ms` above 2147483647 | The value wrapped through a 32-bit integer | Refused by schema validation |

### Required filters with a zone suffix

A `required_filters` value of type `datetime`, `date` or `timestamp` carrying a trailing `Z`, a numeric offset or any other trailing text had the suffix ignored. It is now refused as an invalid value when the filter is resolved for the initial load or for replication. Write the value in the offset configured by `mysql.datetime_timezone`, without a suffix.

### Replication stops on a table map it cannot size

A `TABLE_MAP` event naming a column type this build cannot size now stops replication and reconnects from the last applied GTID, rather than reading the rest of the event from a guessed offset. This applies to every table in the binlog stream, not only configured ones, because the event has to be sized before the table is known to be irrelevant. Every column type MySQL 8.4+/9.x and MariaDB 10.11+ write is decoded; a table still using the pre-5.0 `DECIMAL` storage format is the realistic way to meet this.

### `MYGRAM_API_ADMIN_TOKEN` applies without an `api` section

Setting `MYGRAM_API_ADMIN_TOKEN` was ignored when the configuration file had no `api` block, so a deployment that relied on the variable ran without admin authentication. It now takes effect, and clients of administrative commands need the token. `MYGRAM_MYSQL_HOST`, `_PORT`, `_USER`, `_PASSWORD` and `_DATABASE` likewise apply without a `mysql` block.

### Renaming a table onto a configured name stops replication

`ALTER TABLE other RENAME TO configured` and its `AS` and bare forms were classified as an ordinary `ALTER`, so rows from the renamed table were merged into the index. They are now recognised as a rename in both directions and stop replication with the renamed-table diagnostic.

## Behavior changes

### Replication and loading

- **TABLE_MAP metadata is decoded per column type.** `CHAR`, `ENUM`, `SET` and `DECIMAL` metadata was read with its bytes swapped, and `JSON` and `GEOMETRY` metadata was not consumed, so every later column in the row came from the wrong offset. A metadata block whose declared length does not match what the columns consume now fails the event.
- **MariaDB `COMPRESSED` columns are decoded.** The row image carries the stored payload; it is inflated before indexing, whether MariaDB kept it as-is, deflated it raw or wrapped it in zlib. A payload using an unknown method or failing to inflate stops the row instead of indexing undecoded bytes.
- **Fractional seconds agree.** Required filters on `DATETIME`, `TIMESTAMP` and `TIME` columns with fractional seconds matched different rows at load and during replication. `ENUM` and `SET` labels containing a `SHOW COLUMNS` escape also decode to the same bytes on both paths.
- **A malformed GTID event reconnects** from the last processed GTID, like every other position-carrying event, instead of being skipped.
- **Updates to documents restored without stored text** no longer leave the old postings searchable.
- **A binlog reader that fails to start after a dump restore** leaves the server serving the restored data with replication stopped, as the v1.10.0 notes said it would. Without a restore it is still fatal.
- **`SYNC STOP` and shutdown cancel a running initial load promptly**, and a `SIGTERM` during the initial MySQL connection retries exits cleanly.
- **A malformed row image with an extreme declared field length is rejected** instead of desynchronising the row.

### Search results

- **`FUZZY` results include everything the same non-fuzzy search returns**, including terms shorter than the n-gram size and mixed CJK/ASCII terms.
- **`SORT` on a `bigint_unsigned` column orders values above 2^63 correctly.**
- **A quoted `'not'` after `AND` is a literal term**, not an exclusion.
- **Boolean queries that differ only in full-width whitespace, parentheses or quotes no longer share a cache entry**, so a cached answer always belongs to the query that was sent.
- **`SEARCH` reports its total and its page from one read of the index.**

### Clients and CLI

- **The C++ SDK, the C ABI and `mygram-cli` quote search text, filter values and `AND`/`NOT` terms by one rule.** Full-width and no-break spaces were sent unquoted and split into extra tokens on the server; they now reach it intact, matching what HTTP clients get.
- **Web-syntax expressions convert to a query with the same meaning.** Words such as `order` and `or`, apostrophes, and a minus sign inside a group no longer fail or change meaning, and phrases and OR-groups from `SimplifySearchExpression` are no longer double-escaped.
- **A failed send on a reset connection is an error, not a crash** of the embedding process.
- **Multi-line responses are read completely** with a small receive buffer, including highlighted results, `DEBUG` output and `SHOW VARIABLES`.
- **IPv6 servers are reachable**, by address or by a hostname that resolves only to one.
- **`mygram-cli` prints one row per primary key**, decoding quoted keys that contain whitespace; `DUMP SAVE` prints the server's error code and retries under `--wait-ready`; and `--wait-ready INFO` no longer succeeds while the server still reports `not_ready`.

### HTTP surface

- **`/tables/{identity}/...` requests with a decoded path longer than 256 bytes reach their handler** instead of receiving an empty 404.
- **A non-string `filters.op` returns 400 `kQueryInvalidFilter`**, not 500.
- **A `BIGINT UNSIGNED` filter value above `INT64_MAX` matches the same rows as on TCP** instead of wrapping negative.
- **`mode: boolean` splits on the same Unicode whitespace as TCP**, including U+3000.
- **`trusted_proxies` entries match whatever their textual form**, including an IPv4 peer on a dual-stack listener, and both surfaces derive the same client identity for ACL checks and rate limiting.
- **A second instance can no longer bind an HTTP port already being served.** It fails with `Bind failed (6000)`, as the TCP listener always did.

### TCP surface

- **A failed `SET cache.enabled = true` returns 8001** `kCacheDisabled`, the documented code, and `CACHE ENABLE` names the actual failure.
- **Under thread-pool exhaustion a connection receives `ERROR 6030` and its queued responses** before it is closed, instead of being dropped silently.
- **`SHOW VARIABLES` masks `mysql.ssl_key`** and every other sensitive field, as `CONFIG SHOW` does.
- **Concurrent `SET`s on related variables** no longer leave `SHOW VARIABLES` reporting a value other than the one applied, and `SET cache.min_query_cost_ms` refuses `nan` and `inf`.

### Persistence

- **`DUMP SAVE` refuses a document with an oversized primary key, filter value or text field**, and a dump reported as saved is no longer refused on restore by a stricter memory check.
- **A corrupted index payload with a duplicate term or a short posting blob fails the load** as corrupted, instead of silently dropping postings.
- **`DUMP SAVE .` is refused** instead of writing its temporary file outside the dump directory.

### Docker

- **`docker compose up` refuses a `MYSQL_ROOT_PASSWORD` still set to the `.env.example` placeholder**, as the v1.10.1 notes stated, and the application container now receives the variable.
- **The image's `HEALTHCHECK` follows `API_HTTP_PORT` and `API_HTTP_ENABLE`**, and `docker run <image> version` and `help` print instead of failing on a missing config file.

## Build and dependencies

- CRoaring v5.2.2, cpp-httplib v0.58.0 (chunk-size, trailer-count and ambiguous-framing hardening), googletest v1.18.0 and Abseil 20260817.0. No source changes were needed.
- cpp-httplib's optional TLS and compression backends are disabled explicitly, so the binary no longer links whatever the build host happens to have installed.
- The CMake floor is 3.16, matching Abseil and GoogleTest, and Homebrew prefixes only feed `find_*` lookups.

## Testing

- The e2e matrix targets every supported LTS: MySQL 8.4 and 9.7, MariaDB 10.11, 11.8 and 12.3.
- MySQL-backed tests fail instead of skipping once MySQL integration is opted into.
- New tests decode captured MariaDB 11.8 row images for `COMPRESSED` columns and replicate such a table end to end.

## Specification

- `spec/filter-semantics.md` states that `BINARY`, `VARBINARY` and `BLOB` columns are refused as filters, which is what the code and `spec/config-keys.md` already said.
- `spec/config-keys.md` documents `dump.retain` as read by dump rotation and gives the new upper bounds for the four cache keys above.
- `spec/error-codes.md` records the row-decode sites of 2013 and 2017.
- `spec/tcp-commands.md` no longer describes a reconnect-specific `REPLICATION START` refusal that no code path could raise.
- `spec/surface.snapshot.txt` records those bounds and the `/tables/:identity/...` route patterns.
