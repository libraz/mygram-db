# MygramDB v1.11.1 Release Notes

**Release Date:** 2026-10-22
**Type:** Bug Fix — Lifecycle Safety, HTTP/TCP Agreement, Replication & Storage
**Previous Version:** v1.11.0

---

## Overview

Every change in this release is corrective. It fixes crashes during log rotation and slow shutdown, makes the HTTP surface give the same answers as TCP for boolean queries and unusual table names, keeps replication running through transient source errors while catching more schema changes, and brings the shipped documents and templates in line with what the server does.

A few corrections change whether a configuration starts or which peers are admitted. Those are listed first.

**Highlights:**

- **No crash on log rotation or slow shutdown.** `SIGUSR1` while the server is logging, and a shutdown past the 30 s drain timeout, no longer crash the process.
- **HTTP answers what TCP answers.** Boolean-mode search, count and facet agree on quoted phrases and irregular spacing, and tables whose names fall outside a narrow ASCII set work over HTTP.
- **Replication rides out transient errors.** Deadlocks, killed queries, dropped connections and other retryable errors no longer stop replication or raise a false `SCHEMA_INCOMPATIBLE`.
- **Index changes are re-validated.** `DROP INDEX`/`CREATE INDEX` on a monitored table are checked like `ALTER`, so dropping the primary key's unique index stops replication.
- **Dumps that are saved can be loaded.** `DUMP SAVE` is refused while a table is still loading, and it no longer writes a section the loader would reject.

## Upgrade actions required

### `0.0.0.0/0` and `::/0` admit both address families

A zero-length prefix in `network.allow_cidrs` admitted only peers of its own address family, so `0.0.0.0/0` refused IPv6 clients. Either entry now admits every IPv4 and IPv6 peer on TCP and HTTP, as the schema and `spec/` describe. If you relied on `0.0.0.0/0` to keep IPv6 clients out, list the IPv4 ranges explicitly.

### A regular file at `api.unix_socket.path` stops startup

Startup unlinked whatever it found at the configured socket path, including a regular file. It now removes only a stale socket. Any other file makes startup fail with `kNetworkUnixSocketStale`, and the file is left intact. Move the file or choose another path.

### Runtime `SET` honours `--schema`

A schema passed with `--schema` constrained the configuration at load but not at runtime. `SET` now refuses a value that schema rejects, with `1004`.

### `DUMP SAVE` is refused while a table is loading

`DUMP SAVE` during the initial load wrote a dump that restored as complete. It now returns `ERROR 6029` until every table is ready. Scripts that save a dump right after startup should wait with `mygram-cli --wait-ready`.

### Unsupported table definitions are refused before the snapshot

A composite primary key, or a primary key on a nullable `UNIQUE` column, used to be found only after the initial snapshot had started. The table is now refused with its error code before the snapshot begins.

## Behavior changes

### Lifecycle and logging

- Rotating logs with `SIGUSR1` no longer races a thread that is writing a log line, and a signal that arrives while a reopen is in progress is no longer lost.
- A log reopen no longer reverts a concurrent `SET logging.level`. `SHOW VARIABLES` reports the level in effect.
- A shutdown that runs past the 30 s drain timeout no longer frees state that worker threads are still using.
- When catch-up after a dump restore fails, the server now starts as `not_ready` instead of aborting startup.
- An orphaned dump temp file is reclaimed at startup, including when `mygramdb` runs as PID 1 in Docker and after a crash at the very start of `DUMP SAVE`.

### TCP

- A connection that the server closes with unread input no longer spins the event loop, and the idle timeout now reaps it.
- A connection is no longer closed as idle right after a long-running command replies.
- A request line just over 1 MiB whose CRLF arrives in the same read returns `ERROR 6007`. Previously it returned `6030`.
- A request that overflows the queue during drain receives an error response instead of a silent close.
- Connections rejected over the connection limit no longer flood the log. A peer outside `network.allow_cidrs` is counted as an ACL denial even when the server is at capacity.
- `SYNC STOP` issued while replication is catching up now takes effect.

### HTTP

- Boolean-mode `/search`, `/count` and `/facet` parse quoted phrases and irregular spacing as TCP does.
- Table names containing spaces, `$` or non-ASCII characters are accepted and routed as on TCP. An unknown name returns 404 on both surfaces.
- A JSON body nested deeper than 32 levels is rejected with 400 before it is parsed.
- `HEAD` on probe routes is neither rate limited nor counted, and `HEAD` on a document route no longer returns 404.
- TCP `INFO`, HTTP `/info` and `/metrics` report the same memory and index figures within one snapshot interval.

### Search

- A bare search expression and its parenthesized form return the same results, following the documented precedence.
- Boolean-mode `FUZZY` matches short terms and mixed CJK/ASCII text as flat `FUZZY` does, and it no longer expands terms inside `NOT` with synonyms.
- Search expressions containing byte `0xA0` are no longer split under a UTF-8 locale.

### Replication

- Retryable server errors, among them `1213` (deadlock), `1317` (query interrupted) and connection loss, are classified the same way on the fetch and query paths. They are retried instead of stopping replication.
- `DROP INDEX` and `CREATE INDEX` on a monitored table are re-validated, so dropping the primary key's unique index is detected.
- A failed `SYNC` no longer leaves replication at the snapshot GTID after the table data has been rolled back.
- `ROLLBACK WORK TO SAVEPOINT` and `COMMIT`/`BEGIN`/`XA` statements that carry comments are classified correctly as transaction boundaries.
- A destructive DDL statement is detected even when a harmless statement on the same table comes before it in one event.
- Deleting or updating a row with empty text no longer scans every term or clears the table's query cache.

### Cache and statistics

- An expired entry is counted once in `ttl_expirations`, not once per lookup.
- Stale entries count as misses, and the miss reason matches the debug `cache_reason`, so `hit_rate` and time saved are no longer inflated. Decompression failures are attributed to a miss reason.
- The filter index's reported memory no longer counts string characters twice, and it now includes its map slots.

### Dumps

- `DUMP SAVE` no longer writes a Config, Compatibility or Statistics section larger than `DUMP LOAD` accepts.
- `mygram-cli DUMP SAVE` reports the result of its own save, not the status of another operation.

### Client library and `mygram-cli`

- UTF-8 text is no longer rejected or split under a UTF-8 locale, and whitespace trimming and `SEARCH` header parsing no longer depend on the locale.
- A zero-initialized C search options struct sorts in descending order, as every other search entry point does.
- Threads that share a C client handle each read their own last error.

### Configuration

- A missing YAML configuration reports `1000`, and an empty YAML file reports the empty-file error, as JSON already did.

## Documentation and templates

- `spec/tcp-commands.md` no longer lists divergences that are already fixed, and it states that `DUMP SAVE`/`LOAD` paths are sanitized in replies. `spec/error-codes.md` names the correct place that raises `1008`.
- The documentation states that `SIGUSR1` reopens the log file and `SIGHUP` terminates the server.
- The shipped config templates and the sample systemd unit agree with `spec/`, and the unit allows writing to the suggested log path. The example config marks `memory.minute_epoch` as reserved.
- `support/docker/README.md` names only the compose files and environment variables that exist. Changing `MYSQL_PORT` in `.env` no longer breaks the connection between containers.
- The package verification script writes a configuration that passes `mygramdb -t`.
- The v1.11.0 notes now state that plain `TRUNCATE` clears the index, while partition and tablespace changes stop replication.

## Known limitation

The HTTP allow-list check (`network.allow_cidrs`) runs after the request headers are parsed and before the body is read. A denied peer is answered with 403 without its body being read, but it holds a connection slot until then. The HTTP library has no hook that runs at accept time. `spec/` now describes this ordering.
