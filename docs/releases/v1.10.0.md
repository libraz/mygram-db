# MygramDB v1.10.0 Release Notes

**Release Date:** 2026-08-09
**Type:** Access Control, Replication Recovery & Search Memory Bounds
**Previous Version:** v1.9.0

---

## Overview

Version 1.10.0 closes the network surface by default. An administrative token is required whenever the TCP listener is reachable from off-host, Docker publishes its ports on the loopback address, and a configuration that would expose an unauthenticated administrative surface no longer starts. Both protocols now carry numeric error codes, so clients can branch on a code instead of matching message text.

The release also makes replication recoverable from the one stop condition that could not previously be cleared, and bounds the memory the search path allocates for a broad query.

The fail-closed validation added here can reject configurations that v1.9.0 accepted. Under the project's early-stage SemVer exception these ship in a minor release; read [Breaking & Behavior Changes](#breaking--behavior-changes) and the [Migration Guide](#migration-guide) before upgrading.

**Highlights:**

- **Authenticated administration** — `AUTH` on TCP and `Bearer` on HTTP gate administrative commands, and a non-loopback bind without a token refuses to start
- **Localhost by default in Docker** — published ports bind to `127.0.0.1`, and `API_ADMIN_TOKEN` is mandatory
- **Typed errors on both surfaces** — numeric codes on TCP `ERROR` frames and in HTTP error bodies, with readiness exposed through `INFO`
- **Recovery past an undecodable binlog event** — `SYNC` restarts from the snapshot marker rather than replaying an interval that can never succeed
- **Query cache actually reached** — the cache is now handed to the replication path and the HTTP surface, which previously ran without it
- **Bounded search memory** — candidate text is visited in chunks instead of being copied wholesale for a broad query
- **Startup dump restore** — `dump.load_on_startup` restores a verified dump before falling back to a MySQL snapshot
- **Installable client SDK** — CMake package config, pkg-config, self-contained headers, and boolean-mode search options

## Breaking & Behavior Changes

### 1. Administrative commands require a token

`api.admin_token` is mandatory when the TCP bind is not loopback and no Unix socket is configured. Administrative commands are gated behind `AUTH` issued on the same TCP connection, or an HTTP `Bearer` credential. Tokens are compared in constant time and redacted from request logs.

A configuration that previously served administrative commands unauthenticated on a routable address now fails to start.

### 2. Configuration validation fails closed

Rejected while the configuration is parsed: a public bind with an open CIDR list, CORS without an allowed origin, a TLS listener without a CA, a missing GTID, and a `mysql.user` that cannot be resolved including environment overrides. The built-in schema is validated before any custom schema, so a custom schema can only add constraints, never relax them.

### 3. Runtime MySQL endpoint changes removed

`mysql.host` and `mysql.port` are startup-only, and `SET` on either returns an immutable-variable error. Automatic reconnection to the configured endpoint remains, and rejects a changed source-server UUID. Deployments that relied on runtime failover must change configuration and restart.

### 4. Docker binds to localhost and requires a token

Published API and HTTP ports bind to `127.0.0.1` rather than every host interface. `API_BIND`, `API_HTTP_BIND` and `NETWORK_ALLOW_CIDRS` default to localhost only, and `API_ADMIN_TOKEN` is mandatory in compose with the placeholder value rejected. The in-container listeners moved to `API_CONTAINER_BIND` and `API_HTTP_CONTAINER_BIND`.

### 5. The container entrypoint requires a password

`MYSQL_PASSWORD` has no default. Generating a configuration with a placeholder password produced an instance that could not connect, and the failure surfaced as a replication error rather than as the missing setting it was. The generated configuration is also written under a narrowed umask so it is never world-readable, and `.env` files are excluded from the Docker build context.

### 6. `DUMP SAVE --with-stats` removed

The flag is no longer part of the grammar.

### 7. Cache entries are rebuilt after upgrade

The cache key serializer prefix changed, so entries written by earlier versions are not reused. The first queries after a restart repopulate the cache.

## New Features

### 8. Error codes across both protocols

TCP `ERROR` frames carry a numeric code prefix and HTTP error bodies carry `error_code`. `protocol::ParseErrorFrame` decodes coded and legacy frames through one parser, so a client can branch on a code and still talk to an older server. New codes cover an undecodable binlog event (`2017`), server loading (`6028`), server not ready (`6029`) and server busy (`6030`).

### 9. Readiness on the TCP surface

`INFO` reports `data_initialized` and readiness, evaluated from the same inputs as the HTTP health endpoint, so a TCP-only deployment can gate traffic without polling HTTP.

### 10. Startup dump restore

With `dump.load_on_startup` set, the configured dump is restored before falling back to a MySQL initial snapshot. A dump whose host, port, database, source server UUID or GTID does not match the configured source is rejected, and a GTID is required when replication is enabled. Restored tables are marked initialized before replication restarts, so readiness reflects the restore even if the reader cannot start, and BM25 corpus statistics are rebuilt for them.

### 11. New configuration keys

`cache.invalidation.max_queue_size` bounds pending deferred cleanup identities. `dump.load_on_startup` selects the behaviour above. `api.http.max_connections` and `api.http.trusted_proxies` bound the HTTP surface and decide whose `X-Forwarded-For` is honored. `mysql.ignored_ddl_prefixes` lists statements that must not stop replication.

### 12. HTTP surface hardening

Connection counts are capped, ACL is evaluated before rate limiting, the CORS wildcard and the health-endpoint exemption are gone, `application/json` is required, and errors map to 503 or 500 rather than a generic failure. `POST /optimize` joins the surface alongside denial, dump and pool metrics reported on a monotonic uptime.

## Replication & Recovery

### 13. Recovery past an undecodable event

An XA prepare event or a MariaDB compressed event cannot be decoded by this build, and turning off the server setting that produced it does not remove it from the binlog. Replication can therefore never resume from a position before it.

`SYNC` now recognises this stop reason through error code `2017` and restarts from the snapshot marker instead of the drained pre-SYNC position, logging that the other replicated tables need their own `SYNC` to pick up what the skipped interval wrote. Every other stop reason keeps the drained position, so unrelated tables do not lose commits. A successful start clears the previous run's error, which otherwise made the next operator-initiated stop report a failure and left a stale diagnostic on the status and health surfaces.

### 14. Replication lag is stamped where the position advances

The applied timestamp is now written inside the function that advances the applied GTID. The commit path updated the position under an already-held lock and skipped the stamp, so the lag gauge read as perfectly caught up no matter how far behind replication was.

### 15. Transient and deterministic failures separated

Processing failures are classified as transient transport loss or deterministic, and the same-GTID replay-stop budget applies only to deterministic ones. The failure kind is published atomically so a transient request cannot downgrade a deterministic one, the metadata connection reconnects under the shared backoff rather than through unbacked-off retries, and the processing-recovery attempt counter resets only when the applied GTID advances.

### 16. Transport options are fatal when rejected

A client library that rejects an SSL mode, CA, certificate or key now fails the connection instead of logging a warning and continuing. An unset SSL mode falls back to the client default of `SSL_MODE_PREFERRED`, which turns a configuration demanding a verified server into an opportunistic one.

### 17. Locale-independent input validation

MariaDB GTID positions and initial-load numeric literals are classified by byte range rather than through `<cctype>`, whose answer depends on the process locale. A bare sign or decimal point carrying no digit is rejected, and the filter comparison operator is checked where it becomes SQL syntax rather than only at configuration load. The `TABLE_MAP` and `ROWS` parsers require the full common header before reading the event size field that lives inside it.

## Cache & Search Correctness

### 18. The query cache is reached

The cache is created while the TCP server starts, which is after the binlog reader and the HTTP server are constructed. Both held the null pointer they were built with: row events skipped invalidation entirely, so a cached result kept being served after the row behind it changed, and the HTTP surface ran every request outside the cache while reporting caching as disabled. Both now adopt the cache as soon as it exists.

### 19. Cache keys and queue bounds

Whitespace is no longer collapsed and trimmed when building a key, which let two queries that execution treats differently share one entry. The invalidation queue size limit applies to each pending identity rather than once per batch, its pending and in-flight bytes are charged to the shared cache budget and published as `invalidation_queue_memory_bytes`, and the overflow log reports only the identities actually dropped. LRU maintenance starts only after every eviction callback is installed.

### 20. Storage and query fixes

Restore checks an index section against `dump.restore_memory_budget_mb` before materializing it, and `DUMP VERIFY` refuses a section longer than `dump.restore_max_section_mb` before reading it. A filter column indexed only with NULL values stays visible to column lookup. Highlights over original text are segmented with an ICU character break iterator, so combining marks and halfwidth kana dakuten are not normalized in isolation, with a per-codepoint fallback when ICU is unavailable. Roaring bitmaps are owned through an RAII handle, and publishing an optimized term requires pointer identity as well as a matching version.

## Performance

### 21. Bounded peak memory on the search path

Candidate text is materialized in bounded chunks with the store mutex released, and BM25 scoring, term-frequency counting and every text post-filter — plain, boolean, synonym and fuzzy — use it. Previously a broad query copied a large fraction of the corpus before the first comparison ran.

### 22. Interned filter columns

Per-document filter values are stored against interned column ids in a small sorted vector. A hash map plus an owned column-name string per document and column meant ten million rows with five filter columns held ten million hash maps and fifty million copies of a handful of names. The dump format is unchanged.

### 23. Candidate filtering and posting mutation

A posting list is walked once against a sorted candidate list, so n-gram filtering costs O(candidates + postings) rather than a locked rescan for every candidate and term. Roaring cardinality is tracked exactly through point mutations with the serialized-size estimate amortized, and delta capacity left behind by removals is released instead of being held for the lifetime of the index.

### 24. Invalidation sweeps and maintenance ticks

Dedicated reverse indexes for the filtered and text-sensitive triggers mean a row event visits only the entries it can affect, instead of walking every cache key registered for the table to test one boolean each. Periodic maintenance walks a bounded, resumable slice of the LRU list per tick rather than every entry under the exclusive lock; a cache at or below the slice floor is still covered in a single tick.

### 25. Row images decode only what is read

A row image carries every column of the row, but only the configured key, text sources and filter columns are ever read back. A non-indexed BLOB was decoded and allocated once per INSERT or DELETE and twice per UPDATE for a value nothing consumes; those columns are now skipped, with the pointer still advanced by each field's size.

### 26. Term info reuse and statistics aggregation

One deduplicated term-info lookup is threaded through boolean evaluation, NOT filtering, synonym expansion and verification instead of being regenerated per term, and the full doc-id scan is skipped when the expression has no NOT node. Per-table statistics are aggregated once into a bounded snapshot served to `INFO`, `/metrics` and Prometheus, rather than locking every table for each metric. Cache construction no longer reserves hash buckets from `max_memory_bytes`, which allocated hundreds of MiB for a large empty cache.

## Client SDK & CLI

### 27. The client SDK installs

`MygramDB::client_static` and `client_shared` are exported with a CMake package config, a version file, a pkg-config file, and GNUInstallDirs destinations. The dependency on the internal utility library is gone and the headers install alongside, so they are self-contained once installed. Standalone C and C++ examples ship with the package.

### 28. API additions

`QueryMode` and `MYGRAM_QUERY_BOOLEAN` let a boolean expression combine with filters, sorting, fuzzy matching and highlights. Facet pagination reports a total distinct value count. Expression parse and convert variants return a diagnostic string. Connect, `DUMP LOAD`, `DUMP VERIFY` and `OPTIMIZE` timeouts are configurable, `ERROR` frames are parsed into a typed error, and `MygramSearchOptions_C` fields resolve by `struct_size` for two-way compatibility.

### 29. Deadlines and stricter parsing

A command is polled against one total deadline instead of resetting on partial reads, a response frame is capped, control characters and quotes are rejected in commands and identifiers, and `COUNT` responses are parsed strictly rather than accepting trailing tokens.

### 30. CLI

`--timeout`, `--connect-timeout` and `--retry-interval` are new, and retry and connection-loss decisions come from the server's typed error code rather than matching message substrings, with a compatibility path for untyped replies. `DUMP SAVE [path]` is parsed locally including quoted paths with escapes. Banners, prompts, readline output and error lines go to stderr, so stdout carries only command results.

## Build & Testing

- `FUZZER_ENGINE` selects the standalone driver or libFuzzer, and sanitizer and coverage instrumentation applies to the whole build rather than the harness target alone, so inline and template code is not compiled two ways in one binary.
- Warnings from the vendored JSON library are silenced through the system include path instead of an interface-wide flag that also disabled `-Wall`/`-Wextra` for this project's own sources.
- The end-to-end suite runs against a pinned compose project so teardown cannot reach an unrelated stack, and asserts on named metrics and protocol fields so a renamed or dropped field fails the test instead of silently matching nothing.
- The cross-version matrix covers supported LTS releases only: MySQL 8.4 and 9.7, MariaDB 10.11 and 11.4.
- The full unit suite including the SLOW and LOAD tiers, and the Docker-based end-to-end suite, pass cleanly.

## Migration Guide

Review the following before upgrading, in order of likely impact.

1. **Set an administrative token.** If the TCP listener binds to anything other than loopback and no Unix socket is configured, `api.admin_token` is required and the server will not start without it. Any tooling that issues administrative commands must send `AUTH <token>` on the same TCP connection, or an HTTP `Authorization: Bearer <token>` header. The TCP transport does not encrypt the token; keep that listener on a trusted network or in front of a terminating proxy.

2. **Review the bind and ACL configuration.** A public bind with an open CIDR list is now rejected, as is CORS without an allowed origin and a TLS listener without a CA. Run `mygramdb -t <config>` to confirm the configuration parses before rolling out.

3. **Update Docker deployments.** Published ports now bind to `127.0.0.1`. If the container was reached from another host, move the listener addresses to `API_CONTAINER_BIND` and `API_HTTP_CONTAINER_BIND` and publish deliberately. Set `API_ADMIN_TOKEN` to a real value — the placeholder is rejected — and set `MYSQL_PASSWORD`, which no longer has a default.

4. **Remove runtime endpoint changes.** `SET mysql.host` and `SET mysql.port` now error. Change the configuration file and restart instead.

5. **Drop `--with-stats` from `DUMP SAVE` calls.** The flag no longer parses.

6. **Expect a cold cache after upgrade.** Cache keys built by earlier versions are not reused.

7. **If replication is stopped on an undecodable event,** run `SYNC` for the table that matters first, then for every other replicated table. The first `SYNC` moves the shared stream past the event, so a table that is not rebuilt keeps whatever the skipped transactions would have written.

Dumps written by v1.9.0 load unchanged. Compatibility metadata is now written at version 2, which records the source server UUID; version 1 metadata still restores.
