# MygramDB v1.9.0 Release Notes

**Release Date:** 2026-07-27
**Type:** Search Surface Parity, Replication Fidelity & Correctness Hardening
**Previous Version:** v1.8.1

---

## Overview

Version 1.9.0 unifies search semantics across the HTTP and TCP surfaces, adds typed search options to the C and C++ client APIs, and substantially raises binlog decoding fidelity. It also hardens the dump, cache, query, and reactor paths, and reworks posting-list mutation so indexing no longer blocks unrelated searches.

The release contains fail-closed validation that can reject configurations and commands accepted by v1.8.1. Under the project's early-stage SemVer exception these ship in a minor release; see [Breaking & Behavior Changes](#breaking--behavior-changes) and the [Migration Guide](#migration-guide) before upgrading.

**Highlights:**

- **Cross-surface search parity** — HTTP and TCP route through the same parser, with an explicit literal/boolean mode on HTTP
- **Typed search options** — comparison filters, fuzzy distance, highlight tags and limits, and pagination across the C++ and C APIs
- **Binlog decoding fidelity** — binary JSON, ENUM/SET labels, and negative TIME2 fractional seconds are decoded instead of forwarded as raw bytes
- **Replication position tracking** — received and pending-applied GTIDs are tracked separately and fail closed on a COMMIT/pending mismatch
- **Schema fail-closed validation** — binary column types and non-utf8/ascii collations on configured columns are rejected before replication starts
- **In-place posting mutation** — documents are inserted and removed by patching neighbouring deltas rather than re-encoding whole posting lists
- **Reduced index/search contention** — adding to an existing term takes only a shared map lock
- **Reactor EOF coherence** — read interest and queued events stay consistent after EOF, half-close, and resume
- **Dump internals consolidated** — v1 and v2 share bounded readers and a common restore budget; the document store keeps pre-normalization text (format v3, v1/v2 still load)

## Breaking & Behavior Changes

### 1. Legacy bare `SAVE` and `LOAD` commands are rejected

**Type:** Breaking Change

`SAVE <path>` and `LOAD <path>` now return a migration error (`SAVE is no longer supported; use DUMP SAVE`) instead of executing. Use `DUMP SAVE` and `DUMP LOAD`.

**Files Changed:** `src/query/query_parser.cpp`, `src/query/query_parser.h`

### 2. Configured columns must use a supported type and collation

**Type:** Breaking Change

Configured primary-key, text, and filter columns are validated before replication starts. `BINARY`, `VARBINARY`, and `BLOB` columns are rejected because the snapshot and binlog paths do not share a lossless representation for them. Character columns must use a `utf8mb4_*`, `utf8mb3_*`, `utf8_*`, or `ascii_*` collation; anything else (for example `latin1_swedish_ci`) is rejected. A configuration that previously started will now fail closed with `kMySQLInvalidSchema`.

**Files Changed:** `src/mysql/ddl_schema_validator.cpp`, `src/mysql/ddl_schema_validator.h`

### 3. Configuration identifiers are validated as SQL identifiers

**Type:** Breaking Change

Table, database, primary key, filter, and text-source names are validated while the configuration is parsed. Names that are not valid SQL identifiers are rejected at load instead of being interpolated into generated statements.

**Files Changed:** `src/config/config.cpp`, `src/config/config_loader.cpp`

### 4. `DUMP LOAD` refuses to wipe a non-empty replication position

**Type:** Behavior Change

A `DUMP LOAD` whose payload would clear an existing non-empty replication position is refused. The loaded configuration and GTID are validated together, from the same read, before any live index or document store is replaced.

**Files Changed:** `src/server/handlers/dump_handler.cpp`, `src/storage/dump_format_internal.cpp`

### 5. `SHOW VARIABLES LIKE` requires exactly one pattern

**Type:** Behavior Change

`SHOW VARIABLES LIKE` now requires exactly one pattern argument. The variable surface itself is generated from the configuration projection rather than a hand-maintained map, so it always matches the loaded schema; knobs that are parsed but not yet enforced are labelled as such.

**Files Changed:** `src/query/query_parser.cpp`, `src/config/runtime_variable_manager.cpp`

### 6. `CONFIG VERIFY` resolves paths against the active configuration file

**Type:** Behavior Change

Relative paths passed to `CONFIG VERIFY` resolve against the directory of the active configuration file instead of the process working directory. Scripts relying on the previous behavior need absolute paths.

**Files Changed:** `src/server/handlers/command_handler.cpp`, `src/config/config_loader.cpp`

### 7. Docker environment surface

**Type:** Behavior Change

The stale `SNAPSHOT_DIR`, `SNAPSHOT_INTERVAL_SEC`, and `SNAPSHOT_RETAIN` entries were removed from `.env.example` and the compose file; the entrypoint already read `DUMP_DIR`, `DUMP_INTERVAL_SEC`, and `DUMP_RETAIN`. BM25, cache, rate-limit, and TLS variables are now exposed, the entrypoint validates typed environment values and quotes generated YAML, and it never overwrites an existing bind-mounted configuration file.

**Files Changed:** `support/docker/entrypoint.sh`, `.env.example`, `docker-compose.yml`

## New Features

### 8. Cross-surface search semantics

HTTP search gained an explicit literal/boolean mode, and both transports now route through the shared parser so they agree on query semantics. `FACET` executes on the search pipeline with typed unknown-column errors and offset support, and the pipeline returns `Expected` instead of a success flag with real per-stage counters.

**Files Changed:** `src/server/search_pipeline.cpp`, `src/server/http_server.cpp`, `src/server/handlers/facet_handler.cpp`

### 9. Typed search options in the C and C++ clients

`SearchOptions` and `MygramSearchOptions_C` cover comparison filters, fuzzy distance, highlight tags and limits, and pagination. Two entry points are added: `mygramclient_search_with_options()` and the lossless `mygramclient_convert_search_expression()`. Protocol tokens are escaped reversibly, so primary keys containing whitespace or control bytes round-trip instead of being mangled. Every C entry point is wrapped in an exception barrier, handles allocation failure, validates NULL array elements, and returns a thread-local last-error snapshot.

**Files Changed:** `src/client/mygramclient_c.cpp`, `src/client/mygramclient_c.h`, `src/client/mygramclient.cpp`, `src/client/mygramclient.h`, `src/client/search_expression.h`, `docs/client-api.md`, `docs/client-api_ja.md`

### 10. New runtime knobs

TCP idle-connection reaping (`idle_timeout_sec`, `reaper_interval_sec`) and per-connection pending-frame limits (`max_pending_frames`, `max_pending_frame_bytes`) are configurable instead of fixed constants, and `mediumint` is available as a filter type. Runtime `SET` enforces the schema bounds, and the `mysql.host`/`mysql.port` reconnect is serialized as one transaction. `LoadConfigForValidation` parses without environment overrides and without changing the global log format.

**Files Changed:** `src/config/config.cpp`, `src/config/config-schema.json`, `src/config/runtime_variable_manager.cpp`, `src/server/reactor_connection.cpp`

### 11. SQL generation helpers

`QuoteSQLIdentifier`, `QuoteQualifiedSQLIdentifier`, and hex `EncodeMySQLStringLiteral` keep generated statements semantically identical under `NO_BACKSLASH_ESCAPES`. The loader and binlog paths route identifiers and literals through these helpers instead of local escaping.

**Files Changed:** `src/utils/sql_utils.cpp`, `src/utils/sql_utils.h`, `src/loader/initial_loader.cpp`, `src/mysql/table_metadata.cpp`

## Replication & Loader Fidelity

### 12. Binlog value decoding

MySQL binary JSON, ENUM/SET labels, and negative TIME2 fractional seconds are decoded rather than forwarded as raw bytes, and DECIMAL precision/scale metadata is bounded. A shared value canonicalizer makes TIMESTAMP and DECIMAL text from the binlog match the snapshot representation. Rows events gained bounds checks, and MySQL error codes are reported at a finer granularity.

**Files Changed:** `src/mysql/binary_json.cpp`, `src/mysql/rows_parser_field_decoder.cpp`, `src/mysql/binlog_event_parser.cpp`, `src/mysql/value_canonicalizer.cpp`

### 13. Replication position state

`ReplicationPositionState` separates received from pending-applied GTIDs and fails closed when a COMMIT GTID does not match the pending one. Reconnect backoff is cancellable and resets only after an event is actually fetched from a reopened stream. The server flavor is detected with a capability probe instead of version-string parsing, and MariaDB standalone transactions, GTID list events, and annotate-rows events are handled explicitly; compressed row events are rejected with actionable remediation.

**Files Changed:** `src/mysql/replication_position_state.h`, `src/mysql/binlog_reader_threads.cpp`, `src/mysql/binlog_reader_utils.cpp`, `src/mysql/connection.cpp`

### 14. Streaming initial load

The initial snapshot is fetched with an unbuffered streaming result, checking cancellation between rows and discarding the load connection when the stream is aborted mid-way. Transaction ownership moved to the caller so the result is released before COMMIT or ROLLBACK. Primary key, filter, and text column values are canonicalized so the snapshot matches the binlog representation, and the source table is qualified with its configured database.

**Files Changed:** `src/loader/initial_loader.cpp`, `src/loader/initial_loader.h`

## Storage, Cache & Query Correctness

### 15. Shared dump internals and bounded restore

The streambufs, CRC helpers, and pending-section load/apply logic duplicated between dump v1 and v2 moved into `dump_format_internal`. Length-delimited sections are read through a bounded stream under a shared `RestoreLimits` memory and section budget, enforced on both save and restore. The document store keeps original pre-normalization text (format v3; v1 and v2 dumps still load) and supports chunked normalized-text visiting. Restoring an index preserves the configured Roaring threshold instead of falling back to the default.

**Files Changed:** `src/storage/dump_format_internal.cpp`, `src/storage/dump_format_internal.h`, `src/storage/dump_format_v1.cpp`, `src/storage/dump_format_v2.cpp`

### 16. Cache keying and lifecycle

Each entry stores a canonical query discriminator that is compared on lookup, so a digest collision fails closed instead of serving another query's result. `FACET` queries are cached in the SEARCH DocId namespace. Generation-checked `Erase` lets a caller drop an entry it found semantically stale, and stale entries are evicted after a staleness check rather than left resident. The whole Start/Stop and Enable/Disable transition is serialized under the state mutex, invalidation worker thread creation failure is reported instead of leaving state inconsistent, invalidation registration bytes are tracked incrementally for an O(1) estimate, and the configured `eviction_batch_size` is enforced during the LRU refresh scan.

**Files Changed:** `src/cache/cache_manager.cpp`, `src/cache/query_cache.cpp`, `src/cache/invalidation_manager.cpp`, `src/cache/invalidation_queue.cpp`

### 17. Query parsing and highlighting

Merged highlight windows are clamped to the documented snippet length, and `GenerateOriginal` produces highlights from pre-normalization text. All non-delimiter characters are treated as term characters, so `c++`, e-mail addresses, version strings, and hyphenated terms parse as single boolean terms. The term-count limit is enforced while parsing the AST, the parenthesis-balance check is scoped to the search text, a leading `NOT` parses as a boolean expression, and hex escapes in `GET` keys are decoded. The result sorter's partial-sort threshold was reworked, sort allocation failure is reported, and sort columns are validated instead of sampled.

**Files Changed:** `src/query/query_parser.cpp`, `src/query/highlighter.cpp`, `src/query/result_sorter.cpp`, `src/query/substring_search.h`

## Server & Application

### 18. Reactor EOF and read-interest coherence

Readable and hangup events already queued when a connection reached EOF or paused reads are discarded. EOF is published and read interest disarmed under the frame mutex, so a concurrent drain can neither miss EOF nor re-arm reads. The resume path re-extracts buffered frames before deciding whether kernel reads may restart, `EPOLLRDHUP` is armed only together with read interest so epoll matches kqueue `EV_EOF` semantics, and a partial `Remove` preserves unremoved filters for a later retry.

**Files Changed:** `src/server/reactor_connection.cpp`, `src/server/io_reactor.cpp`, `src/server/reactor/epoll_multiplexer.cpp`, `src/server/reactor/kqueue_multiplexer.cpp`

### 19. Operational hardening

Attacker-driven denial logging is bounded on both transports by `DenialLogLimiter`, and the TCP listener binds over IPv6 as well as IPv4. `SYNC STOP` is an asynchronous cancellation, each `SYNC` gets a coherent configuration snapshot, and the shutdown flag no longer lets replication workers restart. Snapshot scheduler GTID capture and temp-file cleanup were fixed, the top-N fast path is gated on exact semantics, readiness is gated on initial data load, and primary keys are escaped on output.

**Files Changed:** `src/server/sync_operation_manager.cpp`, `src/server/snapshot_scheduler.cpp`, `src/server/connection_acceptor.cpp`, `src/server/denial_log_limiter.h`

### 20. Application lifetime and logging

A signal received during initialization or server startup is reported as an orderly shutdown instead of a startup failure. `RunApplicationInScope` destroys the application before MySQL library teardown in `main`. Every shutdown step runs best-effort, returning the first error while still clearing started state. Per-table initial data readiness is tracked, so manual snapshot mode reports ready only once every configured table is loaded, and the rotating file sink appends across restarts and SIGHUP reopen instead of truncating.

**Files Changed:** `src/app/application.cpp`, `src/app/server_orchestrator.cpp`, `src/app/configuration_manager.cpp`, `src/main.cpp`

## Performance

### 21. In-place posting mutation and reduced contention

Documents are inserted and removed by patching neighbouring deltas in place instead of decoding and re-encoding the whole posting list. Adding to an existing term takes only a shared map lock, so indexing no longer blocks unrelated searches. A posting list converts to Roaring automatically once it exceeds the entry threshold. `PostingList::Deserialize` is overflow-safe and commits strategy and payload only after the full body validates, the V4 index term count is validated against the remaining payload before it is read, and `BM25Scorer::ScoreDocuments` returns `Expected` on parallel-array and batch-length mismatches. The `kDeltaCompressed` strategy was renamed `kFixedWidthDelta` to match the actual encoding.

**Files Changed:** `src/index/posting_list.cpp`, `src/index/posting_list.h`, `src/index/index.cpp`, `src/index/bm25_scorer.cpp`

## Platform & Utilities

### 22. Portable primitives

Datetime conversion uses signed epoch seconds, and `timegm` is replaced with a portable civil-date algorithm that preserves valid pre-1970 values. CIDR matching covers IPv6 and IPv4-mapped IPv6 peers, and `AF_UNIX` connections report a stable `unix` peer identity. `SyncParentDirectory` reports a failure to open the parent directory instead of silently weakening durability. Endianness is detected from the compiler byte-order macros, failing the build on unsupported targets.

**Files Changed:** `src/utils/datetime_converter.cpp`, `src/utils/network_utils.cpp`, `src/utils/atomic_file_writer.cpp`, `src/utils/endian_utils.h`

## Build & Testing

- `ENABLE_UBSAN` builds with UndefinedBehaviorSanitizer and no error recovery; opt-in `BUILD_FUZZERS` wires a local binlog and dump-header fuzz harness that is deliberately not registered with CTest. `mygramdb_add_split_gtests()` labels exact SLOW and CONCURRENCY cases within a single GoogleTest binary while keeping the CMake 3.15 floor. The vendored cpp-httplib pin moved to v0.51.0.
- The E2E interpreter is provisioned through a shared `python-env.sh` used by every entry-point script, with rye as the project standard and a lockfile-based venv fallback. The benchmark seed project carries its own lockfiles instead of resolving dependencies ad hoc.
- E2E gained an autouse fixture that restores the tracked table shape and re-syncs after every DDL test, a `verify_text` post-filter regression test with its fixture table in both the MySQL and MariaDB init SQL, MariaDB non-transactional GTID and checksum-recovery coverage, and a service-independent unit test directory for the wait helpers. Sleeps and magic numbers in the dump, reconnect, memory, and health tests were replaced with polling on observed events.
- Makefile targets were added for MySQL-backed tests, the large dump restore test, and the matrix and failover E2E suites. The benchmark stack works against MySQL 8.4.
- Full unit test suite (SLOW/LOAD included) and the full Docker-based E2E suite pass cleanly.

## Migration Guide

Most deployments upgrade without changes. Review the following before upgrading, in order of likely impact.

1. **Check configured column types and collations.** Text columns must use a `utf8mb4`, `utf8`/`utf8mb3`, or `ascii` character set, and no configured column may be `BINARY`, `VARBINARY`, or `BLOB`. A `latin1` text column that worked in v1.8.1 now fails startup with `kMySQLInvalidSchema`. Convert the column, or drop it from the configuration, before upgrading.

2. **Replace bare `SAVE` and `LOAD` calls.** Any tooling still issuing `SAVE <path>` or `LOAD <path>` must switch to `DUMP SAVE` and `DUMP LOAD`.

3. **Verify configuration identifiers.** Table, database, primary key, filter, and text-source names are now validated as SQL identifiers at load. Run `mygramdb -t <config>` to confirm the configuration parses before rolling out.

4. **Review `DUMP LOAD` automation.** A load whose payload would clear a non-empty replication position is refused. Restoring onto a live instance now requires the position to be empty or consistent.

5. **Use absolute paths with `CONFIG VERIFY`.** Relative paths resolve against the active configuration file's directory rather than the process working directory.

6. **Docker deployments.** `SNAPSHOT_DIR`, `SNAPSHOT_INTERVAL_SEC`, and `SNAPSHOT_RETAIN` are gone from the sample environment; the entrypoint has read `DUMP_DIR`, `DUMP_INTERVAL_SEC`, and `DUMP_RETAIN` since v1.8.1, so update any `.env` still carrying the old names. Regenerate `.env` from `.env.example` to pick up the BM25, cache, rate-limit, and TLS variables. A bind-mounted `CONFIG_FILE` is never overwritten.

7. **`SHOW VARIABLES LIKE` takes exactly one pattern.** Calls passing zero or multiple patterns now error.

Dumps written by v1.8.1 (format v1 and v2) load unchanged. New dumps are written in format v3, which additionally stores pre-normalization text; older builds cannot read them.
