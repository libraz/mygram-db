# MygramDB v1.11.0 Release Notes

**Release Date:** 2026-10-17
**Type:** Replication from TABLE_MAP Metadata, Client ABI 2 & Stricter Source Checks
**Previous Version:** v1.10.2

---

## Overview

This release changes what MygramDB requires of the source server and of programs linked against the client library. Under the project's early-stage SemVer policy these breaking changes ship in a minor version.

Replication now reads column names, signedness and `ENUM`/`SET` labels from each `TABLE_MAP` event instead of querying `SHOW COLUMNS`. A schema query answers for the table as it is now, while a binlog event describes the table as it was when the row was written, and after DDL the two disagree. The source must therefore run `binlog_row_metadata=FULL`. Several other source and table setups that could never replicate correctly are now refused at startup instead of producing a wrong index.

The client shared library moves to soname 2 because two public structs changed layout. C and C++ programs must be rebuilt.

The remaining changes are corrective. Most of them make replication stop, or a request fail, where it used to continue with wrong data.

**Highlights:**

- **Rows decode from the binlog's own metadata.** Column names and types come from `TABLE_MAP`, so rows written before and after an `ALTER TABLE`, a drop-and-recreate or a `RENAME` swap decode against the definition they were written with
- **Unsupported sources are refused before the first snapshot.** Cascading foreign-key children, an intermediate replica that does not log replicated changes, MariaDB's `binlog_storage_engine` and several column formats now fail at startup with a named reason
- **Destructive DDL is detected.** `TRUNCATE` on a configured table clears its index and replication continues. Multi-table `DROP`/`RENAME`, `DROP DATABASE`, partition and tablespace changes and `CREATE OR REPLACE TABLE` stop replication instead of leaving removed rows searchable
- **Replication data is withheld before `AUTH`.** With `api.admin_token` set, `INFO` and `/metrics` no longer show GTIDs and replication counters to unauthenticated clients
- **Tested against every supported LTS.** The e2e matrix covers MySQL 8.4 and 9.7 and MariaDB 10.11, 11.8 and 12.3

## Before upgrading

Read this section before upgrading. The rest of the notes are informational.

### Set `binlog_row_metadata=FULL` on the source

The source server must run `binlog_row_metadata=FULL`. The variable is dynamic, so no restart is needed.

MySQL:

```sql
SET PERSIST binlog_row_metadata = FULL;
```

MariaDB, where `SET GLOBAL` does not survive a restart:

```sql
SET GLOBAL binlog_row_metadata = FULL;
```

```ini
[mysqld]
binlog_row_metadata = FULL
```

If the source runs any other value, startup fails with `2008` before any snapshot is built. The same check runs on every reconnect.

Binlog events written before the change do not carry the metadata. If replication replays such an event for a monitored table, for example after resuming from a dump or a `gtid=` position older than the change, it stops with `2017` and the message names `binlog_row_metadata=FULL`. If older binlogs are still inside the replay window, run `SYNC` for every replicated table after changing the setting.

The sample `docker-compose.yml` starts MySQL with `--binlog-row-metadata=FULL`.

### Sources and configurations that no longer start

| Configuration | What was happening | What happens now |
|---|---|---|
| A table that is the child of a foreign key with `ON UPDATE` or `ON DELETE` `CASCADE`, `SET NULL` or `SET DEFAULT` | InnoDB applies those changes without writing row events, so the index never saw them | Refused with `2012`. MySQL 9.x with `innodb_native_foreign_keys=OFF` is exempt, because the server writes a row event for every child row |
| A source that is itself a replica without `log_replica_updates` (MariaDB: `log_slave_updates`) | Changes replicated into the source never reached its binlog | Refused with `2008`. On MySQL the check runs `SHOW REPLICA STATUS`, which needs `REPLICATION CLIENT` |
| MariaDB with `binlog_storage_engine` set | The engine-integrated binary log has no per-event checksum | Refused with `2008` |
| Any column, configured or not, in old-format MariaDB `TIME(n)`, `DATETIME(n)` or `TIMESTAMP(n)` with `n > 0` (`SHOW COLUMNS` shows `/* mariadb-5.3 */`) | `TABLE_MAP` does not describe the width of such a column, so no row of the table could be sized | Refused with `2012`. Rebuild the column with `ALTER TABLE ... MODIFY`. The same types with `n = 0` are accepted |
| A configured column declared `year(2)` | | Refused with `2012` |
| A primary-key column whose only unique constraint is a `UNIQUE` key that allows `NULL` | A `NULL` key value identifies no row | Refused with `2012`. Declare the column `NOT NULL` |
| A primary-key column that is part of a composite `PRIMARY KEY` or `UNIQUE` key | Rows sharing the configured column were merged into one document | Refused with `2011` |
| No `replication` block and no non-zero `replication.server_id` | Replication is enabled by default, and startup failed only after the initial snapshot | Refused by validation, including `--config-test` |
| `replication.start_from: gtid=...` that is neither a MySQL GTID set nor a MariaDB GTID list | Any value containing `:` was accepted | Refused. MariaDB `domain-server-seq` lists are now accepted |
| A `network.allow_cidrs` entry in IPv4-mapped IPv6 form with a prefix shorter than 96 | The entry never matched | Refused. With a prefix of 96 or more the entry is folded into the IPv4 range and matches IPv4 peers |
| `memory.hard_limit_mb` or `memory.soft_target_mb` above 2147483647 | | Refused by schema validation |

### Name matching follows `lower_case_table_names`

When the source runs `lower_case_table_names=0`, database and table names in the binlog now match configured names byte-exactly, on the row path and the DDL path alike. DDL used to match case-insensitively regardless of the setting. With any other value both paths match ASCII case-insensitively. Check that every `tables[].name` and `tables[].database` uses the exact case the source stores.

### Rebuild C and C++ clients

The client shared library is now `libmygramclient.so.2` (VERSION 2.0.0). Two public structs changed layout:

- `SearchExpression` gained `required_is_group` and `excluded_is_group`, which mark the required and excluded entries that are parenthesized groups, and lost `optional_terms`.
- `MygramParsedExpression_C` lost `optional_terms` and `optional_count`, which were always empty.

Programs built against the v1.10.x headers must be rebuilt against the new ones.

### `mygram-cli DUMP SAVE` reads the path as the server does

The path is the last non-empty token of the line, decoded with the server's escape set. It used to be the rest of the line. A `DUMP SAVE` line that carries a `-` flag is sent to the server unchanged, and the server rejects it. Quote a path that contains spaces.

### Runtime `SET` follows the configuration schema

`SET` checks each value against the same schema rule the configuration loader applies, and refuses a value the loader would refuse with `1004`. A multi-assignment `SET` applies all assignments or none, and the error names the assignment that failed. The `server_id` check and the `cache.max_memory_mb` ceiling of 50% of physical memory now apply to `SET` as well as to startup.

### Oversized documents fail ingestion

The document-field limits that dumps enforce now apply when rows enter the index: primary key 1 MiB, at most 1,000 filters per document, filter name 1 KiB, string filter value 64 KiB, normalized and original text 16 MiB each. A row over a limit fails the initial load or `SYNC` explicitly. During replication it reports the limit error and does not advance the GTID position. Such a row used to be indexed and then make every later `DUMP SAVE` fail.

`used_memory_index` now counts per-term object and map overhead, so the memory admission checks for `OPTIMIZE` and `DUMP SAVE` see a larger figure than before and can refuse an operation that was admitted on v1.10.2.

### Replication data is withheld before `AUTH`

When `api.admin_token` is set, the `# Replication` section of TCP `INFO` is omitted for a connection that has not completed `AUTH`, and HTTP `/metrics` omits every `mygramdb_replication_` metric unless the request carries the bearer token. Both stay public. Monitoring that scrapes these values must now authenticate.

### HTTP status codes follow the error code

HTTP errors now take their status from one mapping of the error code, listed in `spec/error-codes.md`. Changes a client can see:

- A bare table name under a multi-database configuration returns 404 with `4007`, not 400 with `3000`.
- `GET /replication/status` returns 200 with `{"enabled":false,"status":"not_configured"}` when replication is not configured, as TCP does.
- `GET /config` with no configuration loaded returns 503 with `6026`, the code TCP `CONFIG SHOW` returns.
- A `limit` above 1000, more than 64 filter conditions, and an invalid facet column return 400 with `3000`, matching TCP.

## Behavior changes

### Replication and loading

- **A monitored `TABLE_MAP` with missing or malformed optional metadata stops replication with `2017`.** It used to reconnect forever, because the event stays in the binlog as written.
- **A `TABLE_MAP` naming a column type this build cannot size stops with `2017`.** v1.10.2 reconnected from the last applied GTID, which met the same event again. The stop leaves recovery to `SYNC`.
- **Destructive DDL on a configured table is detected.** `TRUNCATE`, `DROP TABLES` and `RENAME TABLES` lists, statements carrying `#` or executable comments, and unquoted names with non-ASCII characters or `$` are recognized. A plain `TRUNCATE` clears the table's index and replication continues. Partition `DROP`/`TRUNCATE`/`EXCHANGE`/`CONVERT`, tablespace `DISCARD`/`IMPORT` and `CREATE OR REPLACE TABLE` stop replication with `2017` so that `SYNC` rebuilds the table. `DROP DATABASE` of a configured database stops with `2012`, in any identifier case.
- **Statements are read under the `sql_mode` they were logged with.** `ANSI_QUOTES` and `NO_BACKSLASH_ESCAPES` change where a statement ends. A stored-program definition is read as the rest of its event, so a `TRUNCATE` inside a procedure body is no longer taken for one run against a configured table.
- **A `1236` dump error stops with `2008` unless the source says the required GTIDs were purged.** Only a purged position sends the operator to `SYNC`. A replica ahead of the source, an oversized packet or a corrupt binlog report the server's message instead.
- **On MariaDB, `REPLICATION START` refuses a purged position up front** instead of answering OK and stopping afterwards.
- **Transient fetch errors reconnect.** A source restart, kill or maintenance window no longer stops replication until an operator intervenes. A truncated frame reconnects instead of being skipped or passing without a checksum check, and events still queued from the old stream are dropped on reconnect.
- **Each binlog file is read with its own checksum algorithm**, so files written with `binlog_checksum=NONE` before the setting was changed still stream.
- **Unknown event types flagged ignorable by the source are skipped.** Without the flag the stop reports the raw type number.
- **`replication.start_from: gtid=UUID:N` means "through N".** The position is widened to `UUID:1-N` once, so later reconnects do not ask the source for earlier transactions again. Transaction numbers at or above 2^63−1 are refused, as the source refuses them.
- **A malformed GTID is rejected before it reaches `SET GTID_NEXT`**, and GTID set comparison rejects the same malformed values the encoder rejects.
- **A row event with a `NULL` or missing primary key fails closed** instead of advancing the received GTID.
- **On MariaDB, the initial snapshot's position is the snapshot's own binlog position**, converted to a GTID, instead of a separately read `gtid_binlog_pos`.
- **The initial load and replication admit the same rows.** A `required_filters` column whose value fails conversion, such as a zero `DATE` or a `TINYINT(1)` holding 2, is judged from its raw text on both paths, so such rows are no longer loaded and then dropped by the first replicated update. `TIME(n)` filters agree on MariaDB.
- **Temporal `required_filters` no longer force a full table scan** during the initial load.

### Search and cache

- **Different queries no longer share a cache entry.** Outside boolean mode the key is built from the search text, so quote characters folded by normalization no longer merge two queries.
- **A query still executing cannot overwrite a newer cache entry.** A result is cached only if no matching write or data-version change happened while it ran; otherwise the insert is rejected and counted in `cache_rejections`. Slow queries can be cached while replication applies rows, and a cache insert no longer evicts the entry it has just admitted.
- **No stale results after a cold start.** With replication enabled, cached results are not served before the cache is wired to replication.
- **A `NOT` term too short for n-grams returns `ERROR 4000`** when the table has no normalized text for substring fallback, instead of being ignored.
- **`FILTER` behaves the same on every search path** for a boolean filter with an unrecognized value and for a numeric `!=` with an unparseable value.
- **U+0085 separates terms and U+200B does not**, following Unicode `White_Space`. An unquoted query containing a zero-width space no longer matches nothing.
- **Lowercasing no longer depends on the host locale**, so a dump searches the same on every host.
- **`FACET` values with equal counts come back in a stable order**, so `OFFSET` paging no longer repeats or skips values.
- **`DEBUG ON` output for `SEARCH` and `COUNT` includes the `cache_key` line** whenever a canonical key exists.

### TCP surface

- **`SHOW VARIABLES LIKE` matches case-insensitively**, and `SHOW VARIABLES` and variable lookup agree on the variable list, including `network.allow_cidrs`. After `CACHE ENABLE` or `CACHE DISABLE`, `SHOW VARIABLES` reports the current `cache.enabled`.
- **A failed multi-assignment `SET` changes nothing** and no longer overwrites a concurrent change.
- **`CACHE ENABLE` retries the invalidation worker** after an earlier start failed.
- **`SYNC STATUS` reports a fixed duration for a completed sync** instead of one that keeps growing.
- **`REPLICATION START` and `STOP` can no longer race a `DUMP SAVE`** and record a GTID from a stopped reader. A missing replication reader is reported as an error.
- **During shutdown, new `SYNC` and `OPTIMIZE` requests are refused** while an in-flight dump finishes.
- **No response is written after the terminal overload error frame.**

### HTTP surface

- **HTTP and TCP return the same error code for the same fault**; see [HTTP status codes follow the error code](#http-status-codes-follow-the-error-code).
- **`DOUBLE` filter values match like TCP `FILTER`**, using the shortest round-trip representation instead of six fixed decimals.

### Dumps and snapshots

- **`DUMP SAVE` refuses what the loader would reject**: a section over the fixed 4 GiB limit, an oversized config string or table name, and V1 config and statistics payloads over 16 MiB.
- **Malformed dumps fail to load**: a V2 file with the CRC flag cleared, a wrong section count or trailing data, and a document with DocID 0. A failed load leaves the live document store untouched.
- **A server whose DocID counter is exhausted can reload its snapshot**, and a save in that state reports the exhaustion explicitly.
- **The index payload is written through an atomic, fsynced temporary file** instead of in place.
- **Scheduled snapshots wait for the initial load**, so an empty snapshot no longer replaces a good one.
- **Orphaned dump temporary files are cleaned up at startup even with `dump.interval_sec: 0`.** Only aged files whose owning process is gone are removed, and a completed dump whose name ends in `.tmp` is no longer deleted.
- **Dump paths containing control bytes are refused**, and `DUMP SAVE`/`DUMP LOAD` replies no longer echo control characters from the path.

### Clients and CLI

- **Replies are framed per command.** A `FACET` reply no longer desynchronizes the connection, `CONFIG HELP <path>` returns its full text, a failing highlighted or `DEBUG` search returns its error at once, and a quoted term containing the word `highlight` no longer times out.
- **`SendCommand` tracks `DEBUG ON`/`OFF`**, and lowercase or irregularly spaced `OPTIMIZE`, `DUMP LOAD` and `DUMP VERIFY` get the long-operation timeout instead of 30 seconds.
- **Names containing whitespace are rejected client-side.** Table, column, filter-key and `SetVariable` names with Unicode whitespace no longer split a command.
- **Web-syntax expressions keep their meaning.** A negated nested group excludes the whole group, a quoted phrase shaped like a group stays a phrase, and terms beginning with `OR`, such as `OR-tools` or `OR回路`, are not read as the operator.
- **Quoting follows Unicode `White_Space`**: U+0085 is quoted as whitespace, U+200B is not, and bare tokens carrying a quote or backslash are quoted.
- **The client library parses and formats numbers independently of the host application's locale**, and `GET` key-value pairs with a malformed quoted value are rejected.
- **`mygram-cli` sends command lines verbatim.** In arguments a tab becomes a space and other control bytes are dropped. `DOC` values are decoded with the library's decoder.
- **`mygram-cli --wait-ready` exits non-zero** when the server is still not ready after the retries.

### Configuration

- **`api.tcp.max_pending_frame_bytes` is independent of `api.max_query_length`.** The load-time cross-check compared bytes against characters and is gone.
- **Schema descriptions, `CONFIG HELP` text and `examples/` match behavior**: CORS needs `cors_allow_origin`, `kanji_ngram_size` applies to CJK ideographs only, `memory.verify_text` does not control text retention, `logging.file` is recommended rather than required with `--daemon`, and `--schema` adds constraints but cannot add keys.

## Specification

- `spec/config-keys.md` gains "Server requirements", "Stream handling" and "Table requirements" sections with the code for each refusal, and an "Ingestion value limits" section. It documents the GTID grammars for `replication.start_from` and the new bounds for `memory.*` and `cache.max_memory_mb`.
- `spec/error-codes.md` lists the HTTP status mapping and ties `2008` and `2012` to the server and table requirements.
- `spec/http-routes.md` records the new statuses and codes, the `/metrics` credential behavior and the `GET /replication/status` reply without replication.
- `spec/tcp-commands.md` records the `INFO` gating and the `cache_key` line.
- `spec/persistence-formats.md` states the writer limits and the V2 CRC flag requirement.

## Migration Guide

1. Set `binlog_row_metadata=FULL` on the source and, if older binlogs remain in the replay window, plan a `SYNC` for each replicated table.
2. Check the source and table setups under [Sources and configurations that no longer start](#sources-and-configurations-that-no-longer-start), and the exact case of configured names under `lower_case_table_names=0`.
3. Rebuild C and C++ programs against the new client headers and `libmygramclient.so.2`.
4. Give monitoring that reads replication values from `INFO` or `/metrics` the admin token.

The dump format version is unchanged. Dumps written by v1.10.2 load without migration.
